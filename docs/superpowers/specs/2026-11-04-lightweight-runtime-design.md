# Lightweight Soul runtime

## Intent and approved direction
User approved batching ordinary memory for about1–2minutes, prioritizing explicit remember requests, compact extraction inputs, independent resource budgets, incremental context and smaller connect output. Product goal: installing/connecting a Soul should add no perceptible everyday waiting or substantial resource spend. This is a measured target, not a promise of zero network/LLM latency.

## Approaches
1. Only cap hook duration: already shipped; leaves model frequency and token growth unchanged.
2. Batch background work plus bounded input/budgets and per-session delivery deduplication (chosen from the user's approved recommendation).
3. Centralize extraction on a new hosted model: rejected; adds credentials, server cost and raw-conversation egress.

## Constraints
Work only in runtime worktree, preserve auth/consents/session source boundaries, all existing hosts, native tools-denial and per-turn provenance. No changes to Rails, original HOME or production installation. No new dependencies, npm publication, new provider credentials, raw transcript upload, silent loss of queued memory, or misleading zero-cost guarantees. Node>=18. Full runtime npm test required; no Rails tests. Commit tested work; merge/push/release remain separate from this implementation.

## Behavior
- Hooks remain local and bounded by existing300ms/50ms processing deadlines. They do not run extraction/cloud requests. No new per-tool polling or foreground model call.
- Ordinary completed turns remain durable pending watermarks. Production worker prepares them locally; up to3 turns from the same profile/device/runtime/native session/binding revision may share one native model invocation. Start when3 are ready, a user explicitly requests memory, or the oldest has waited90seconds. Daemon30second fallback means ordinary persistence normally within120seconds after completion. Other sessions/Souls never share batches. Keep existing direct schedule API immediate for explicit/manual callers and existing tests.
- Batch output maps each job UID to its own proposals; parse and commit independently through each original adapter/request. Missing/duplicate/foreign job IDs are errors, not an empty-memory success. Failed/stale source/changed binding cannot be attributed to another turn. Do not clear original pending jobs on budget deferral.
- Use native adapters' existing renderers to prepare a turn. Cap tool material first, deduplicate identical tool messages, remove embedded binary/data URLs, preserve human vs assistant vs tool provenance. Ordinary text is bounded with explicit omission markers. Oversized explicit human instructions stay queued with an actionable diagnostic rather than being silently truncated/declared remembered. Target total extraction input<=24KiB; per-turn material<=6KiB excluding shared rules; output instruction<=1024tokens. Batches split before exceeding input limit.
- Budget is local conservative accounting, never a dollar invoice: cap40native invocations/day/profile and20/day/session, plus200000reserved input/output units/day/profile and50000/day/session. Reserve conservatively using UTF-8bytes plus1024output allowance before invocation in the writer's same transaction as claims. No attempt is spent when deferred. Reservations may overcount failed calls; never falsely report them as actual billed usage. Track provider-reported usage separately where available. Retain at most8days of aggregate metadata. Daily UTC rollover resumes pending work. Explicit memory does not bypass safety limits. Claude gets a hard output-token env limit and thinking disabled for extraction only; other native hosts retain their existing argv without a new claim of verified tool denial and have prompt/output-size/process guards. Do not claim an unverified universal provider hard token cap.
- Production drain concurrency stays1. Source/model work is outside writer FIFO; claims/commits stay serialized. Native model timeout remains60seconds. Internal extraction cannot recursively extract itself.
- Injection is per exact session+binding revision, recorded only after delivery. Unchanged rendered context can be omitted on later prompts. Restore full context on SessionStart/resume/reset/compact/changed source or binding; memory/identity revision changes deliver updated context. A shortened context cap4096bytes (identity<=2048, relationships<=8, experience<=4) applies only to hook output, not stored assets or full recall. Compaction may require a fresh explicit boundary under existing fail-closed source rules; never infer another session.
- Connect keeps ownership lookup and live authorization checks; do not trade consent/revocation security for a local-cache fast path. Compact successful connect output includes you_are, host's basic persona, mood, relationship, directive, core_version and connection; retain required first-person guidance, omit photos/video/circle/thread/upcoming/long product guidance. `whoami` remains full detail. Reduce directory request only if an authoritative endpoint already supports it; do not infer account-wide uniqueness from a partial local cache.

## Measurement
Compare fixed synthetic turns against baseline0.15.5: actual native invocation count, compact input/output bytes, repeated injected bytes, fresh-process hook/recall latency and daemon peak RSS with extraction children separated. Local mock native subprocess proves real argv/schema/protocol; do not call it a live-model benchmark. No extra paid model calls without a new bounded allowance (previous10call test authorization was exhausted). Ordinary memory may be delayed; explicit memory prioritized, not a synchronous promise that the cloud already saved it.

## Review focus
Budget exhaustion or restart must not lose memory; cross-Soul/session/account isolation; source replacement or compaction during batching; injection dedupe must not suppress required restoration; malicious/huge tool text and reordered/missing/duplicate model jobs cannot fabricate or misattribute memories.

## Builder rulings
Batch coalescing enabled only for Claude/Pi explicit tools-denial surfaces; other hosts keep individual calls with the same cadence and resource bounds, pending further native verification. Context suppression enabled only for native Claude; other bridges retain bounded full injection until consumer retention/restoration is independently verified. Stale binding work stays frozen, unclaimed and visible as stale_binding; returning to a Soul or UTC rollover never revives/relabels it. This preserves existing stale-source safety, at the cost of deferred tasks requiring an explicit safe recovery rather than guaranteed completion after role switches.
