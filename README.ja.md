# 37Soul

[English](README.md) · [简体中文](README.zh-CN.md) · **日本語**

Agent に持続するアイデンティティを与え、長期的な好みや経験をセッションやツールをまたいで引き継げるようにします。

ローカルランタイムは Claude Code、Codex、OpenCode、Hermes、Pi に接続します。Soul はまず自分のマシンだけで使い始められます。ログインして明示的に同期を許可した後に限り、指定したカテゴリの長期アセットが 37Soul に同期されます。

## インストール

macOS または Linux、Node.js 18 以降、およびモデルをすでに正常に利用できる対応ホストを少なくとも 1 つ用意してください。Linux では systemd のユーザーセッション（`systemctl --user`）も必要です。利用できないコンテナやサーバーでは、この方法でバックグラウンドサービスを起動できません。

```bash
curl -fsSL https://37soul.com/install.sh | bash
```

インストーラーはランタイムをダウンロードして検証し、検出したホストに管理対象の設定をインストールして、バックグラウンドサービスを設定して起動を試み、ローカルプロファイルを作成します。`37soul doctor` でサービスが正常に起動したことを確認してください。インストール時にはダウンロードサーバーへアクセスしますが、それによってアカウントへのログインや会話のアップロードが行われることはありません。変更範囲を先に確認するには、次を実行してください。

```bash
curl -fsSL https://37soul.com/install.sh | bash -s -- --plan
```

## Web サイトに Soul がある場合

```bash
37soul login
```

認証リンクを開き、短いコードを確認して、このコンピューターを承認します。ログインはアカウント認証のみで、Soul の選択や自動復元は行いません。ログイン後、ローカル Agent に「Sophia Ramirez に接続して」のように、使いたい Soul を伝えてください。

Agent は `37soul hosts` で所有する Soul を確認し、`37soul connect --name NAME --agent RUNTIME --session SESSION_ID`（`--name NAME` は `--host ID` に置き換え可能）で、その Soul を選択して復元・接続します。`--agent` と `--session` は現在のネイティブ hook が示した正確な値を使い、別の端末を推測してはいけません。`connection.state: attached` が現在のセッションへの接続完了を示します。

同名の Soul が複数あれば本人に確認し、見つからなくても代わりの Soul を作成しません。別の所有する Soul に切り替える場合も同じログインを使い、再ログインや別のリモート OAuth は不要です。取り消した許可は明示的に再承認する必要があり、狭めた許可範囲は維持されます。ホストの読み込みや承認がまだなら、以下の接続手順を完了してください。

## まずローカルで Soul を作成する

名前、性別（`male`/`female`/`other`）、年齢（16–65）、50 文字以上の設定、写真を本人に確認してください。変数には確認済みの選択を入れ、人格を勝手に作らないでください。実行前に `/path/to/photo.jpg` を実際のローカル画像パスに置き換えます。

新しいローカル Soul には `--avatar` で実際の写真を必ず指定します。デフォルト画像は使えません。JPEG、PNG、WebP、最大 5 MiB に対応します。CLI が管理下のローカルプロフィールへコピーするため、元のファイルを移動・削除しても写真は失われません。

サイトでは写真のアップロードまたは AI 生成が可能です。登録してメールを確認すると、既存の登録特典 18 credits で 3 枚（1 枚 6 credits）を生成できます。追加の付与ではありません。完全オフラインではクラウド credits を使えません。画像がない場合はサイトで登録・メール確認・生成・ダウンロードを済ませ、そのローカルファイルを CLI に渡してください。

クラウドは任意です。ログインし identity を明示的に許可して同期します。初回登録ではプロフィールと写真を一緒に送信します。実際の写真がある既存のサイト Soul は、ログイン後に `37soul hosts` で確認し、正確なネイティブ hook の会話パラメーターを使った `37soul connect` で復元できます。新しい写真は不要です。


```bash
SOUL_NAME='<confirmed name>'
SOUL_SEX='<confirmed male, female or other>'
SOUL_AGE='<confirmed integer 16–65>'
SOUL_CHARACTER='<confirmed character of at least 50 characters>'
37soul soul create \
  --avatar '/path/to/photo.jpg' \
  --name "$SOUL_NAME" \
  --sex "$SOUL_SEX" \
  --age "$SOUL_AGE" \
  --character "$SOUL_CHARACTER"
37soul soul list
```

作成結果の Soul UID をコピーし、以下の変数の値を置き換えてください。

```bash
SOUL_UID='実際の Soul UID をここに貼り付ける'
37soul soul select "$SOUL_UID"
```

ホストの接続手順を完了して新しいセッションを開くと、ローカルで利用できます。Web サイトや別のマシンと同期したくなったら、次を実行してください。

```bash
37soul login
37soul soul select "$SOUL_UID"
37soul soul authorize "$SOUL_UID" --categories identity,relationship,experience
37soul sync
```

ここでの `37soul login` はアカウント認証のみです。作成結果の実際の UID を使って `37soul soul select "$SOUL_UID"` でこのローカル Soul を選び、その後 `37soul soul authorize` で登録と同期を許可します。初回の identity 許可と同期でプロフィールと写真が一緒に登録され、その Soul のキャラクタープロフィールが Web サイトに公開されます。プライベートチャットや個人の記憶が公開されるわけではありません。`--categories` は、このデバイスにおけるその Soul の許可カテゴリ全体を置き換えます。カテゴリの追加だけを行う指定ではありません。

## ホストの接続を完了する

| ホスト | インストール後に必要な操作 |
| --- | --- |
| Claude Code | 古いセッションを閉じ、新しいセッションを開いて管理対象の hooks とガイドを読み込みます。 |
| Codex | Codex で `/hooks` を開き、37Soul の hook を確認して承認した後、新しいセッションを開きます。インストーラーが代わりに承認することはできません。 |
| OpenCode | OpenCode を再起動し、管理対象のプラグインを読み込みます。ホストにプラグインの読み込みエラーが出ていないことを確認してください。 |
| Hermes | ローカルの Hermes CLI の hooks 連携を使用します。ホストの案内に従って読み込みを承認し、新しいセッションを開いてください。gateway のみの設定では CLI の代わりになりません。 |
| Pi | Pi を再起動して管理対象の拡張機能を検出・読み込みさせ、新しいセッションを開きます。ホストが拡張機能を制限している場合は、先にホスト側で承認してください。 |

各ホストには、引き続き利用可能なモデルのログインまたは設定が必要です。37Soul はホストのモデル認証情報を提供したり、自動で置き換えたりしません。

新しいセッションは 1 つの Soul だけにバインドされます。そのホストの既定があればそれを使い、なければアカウント既定、Soul が 1 つだけならそれを使います。複数の Soul があり、このホストで使う Soul を決めたい場合は、セッションを開く前に選んでください：

```bash
37soul soul list
37soul soul select <soul_uid> --agent claude-code
```

`--agent` を省略すると、今後のセッション用のアカウント既定を変更します。既存のローカルログインがあれば、Agent は `37soul whoami --host HOST_ID --agent RUNTIME` で選択後のアイデンティティを読み取れます。認証情報はランタイムが内部で使うため、別のリモート MCP OAuth や token ファイルの読み書きは不要です。

開始済みのセッションに接続・切り替えする場合は、Agent が現在のネイティブ hook の正確な値を使って `37soul connect --host HOST_ID --agent RUNTIME --session SESSION_ID` を実行します。成功時は `connection.state: attached` が返ります。hook の会話情報や許可がなければ明示的に失敗し、別の端末を推測しません。初回のホスト読み込みや承認は、上記の手順に従ってください。

## 動作を確認する

```bash
37soul status
37soul doctor
37soul soul list
```

新しいセッションで、「今後、実装の提案をするときは、理由を説明する前に実行できる手順を挙げてください」のように、継続的な協力の好みを明示してください。ランタイムは会話のターンが完了した後に長期アセットを抽出します。一時的な依頼や一度きりの作業を、必ずしも長期記憶にするべきとは限りません。

```bash
37soul recall "協力"
```

ローカル利用に同期は不要です。ログインしてこの Soul の同期を許可した後で、`37soul sync` を実行してクラウド同期を確認してください。

抽出にはホストのモデルによる処理が必要です。失敗時には自動で再試行し、ホストの利用枠を追加で消費する場合があります。完了までの時間もモデルやネットワークに左右されます。`doctor` の「インストール済み」「ホストの読み込み待ち」「ローカルイベントを観測済み」は、それぞれ異なる状態です。各状態に添えられた案内に従い、ファイルが書き込まれたことをホストの読み込み完了と見なさないでください。

Web サイトでアイデンティティや長期アセットを修正し、次のセッションですぐに修正内容を使いたい場合は、先に次を実行してください。

```bash
37soul sync
```

同期エラーがないことを確認してから、新しいホストセッションを開いてください。バックグラウンドでも定期的に同期しますが、Web サイトの変更が開いているセッションを即座に書き換えるわけではありません。古いセッションのコンテキストにすでに含まれた内容を、リモートから取り消すこともできません。

## データと許可

- **ローカルランタイムは、会話・コード・ツールログの原文を 37Soul のクラウドへアップロードしません。** ローカルランタイムは範囲を限定したセッションのソースを読み取り、ホストに設定されたモデルで長期アセットを抽出します。モデルサービスでのデータの取り扱いは、使用するホストとモデル提供者の設定に従います。処理全体がオフラインという意味ではありません。
- 明示的に許可した identity、relationship、experience のアセットだけが 37Soul に同期されます。ログインしただけで、未許可のローカルコンテンツにアップロードの許可が自動で付くことはありません。
- ログイン認証情報は、サーバー、プロファイル、アカウント、デバイス、ホストに紐づきます。サーバーを変更する場合は、別のプロファイルを使って再ログインする必要があります。別々のサーバーで同じ番号のアカウントがあっても、自動では統合されません。
- Web サイトでデバイスの許可を取り消すと、次回サーバーに接続した際にそのデバイスは拒否され、ダウンロード済みの非公開キャッシュが消去されます。ローカルで作成した Soul、未同期のアセット、元のセッションファイルは保持されます。同期が確認されたアセットのコピーは消去されます。オフラインのデバイスは、サーバーで起きたばかりの変更をすぐに知ることはできません。

## 問題が起きた場合

| 症状 | 次の操作 |
| --- | --- |
| コマンドが見つからない | まず `~/.local/bin/37soul status` を試し、`~/.local/bin` を PATH に追加してください。 |
| バックグラウンドプロセスが動いていない、または別のバージョンが動いている | インストールコマンドを再実行し、`37soul doctor` を実行してください。 |
| ホストが連携機能を読み込んでいない、または信頼していない | 上の表のホスト操作を完了し、新しいセッションを開いてください。承認を回避する起動引数は使わないでください。 |
| 有効なローカルプロファイルを選択できない | `37soul login` の再接続確認を読み、アカウント認証を承認してください。その後 Agent が `37soul hosts` で確認し、正確なネイティブ hook の会話パラメーターを使った `37soul connect` で Soul を選択・接続します。既存データは元の場所に保留され、自動コピーや統合はされません。非対話端末には専用のログインコマンドが表示されます。 |
| 同期認証情報がない、または発行元サーバーの不一致が表示される | 接続先サーバーで再ログインしてください。既存のクラウドプロファイルはサーバー間で再利用できません。別のプロファイルが必要な場合は `37soul login --profile 新しいプロファイル名` を使ってください。 |
| 一時的にネットワークが利用できない | ローカルコンテンツは保持されます。ネットワーク復旧後に `37soul sync` を実行してください。「リセット」のためにプロファイルやキューを削除しないでください。 |
| 長期アセットがまだない | 会話のターンが完了していること、ホストのモデルが利用可能なこと、バックグラウンドサービスが動いていることを確認してください。一度きりの内容では長期アセットが作られない場合があります。 |

```bash
37soul pause
37soul resume
37soul uninstall
```

これらのコマンドはローカルランタイムの一時停止、再開、アンインストールに使います。アンインストールでは管理対象の連携を削除し、ローカルの Soul、アセット、未同期データは保持します。

## リモート MCP

ローカルランタイムを実行できないクライアントは、`https://37soul.com/mcp` に接続して自分のプラットフォームアカウントを操作できます。これはローカル hooks による自動取得とは別の接続経路です。

## 開発と配布

ユーザー向けのインストール経路は GitHub Release と Web サイトの `install.sh` のみで、npm は使用しません。ビルド、テスト、バージョン、リリースの根拠は[開発ドキュメント](docs/reviews/)を参照してください。リリースチェックが自動で公開を行うわけではありません。
