# 37Soul

[English](README.md) · **简体中文** · [日本語](README.ja.md)

**电脑你选，模型你选，让你的 Agent 越来越懂你。**

为本地 Agent 加上持续的身份、长期记忆和与你的关系。换项目、换已支持的工具、换已授权的设备，也能延续熟悉的协作方式。

[这是什么](#1-这是什么) · [为什么要用](#2-为什么要用) · [怎么开始用](#3-怎么开始用)

## 1. 这是什么？

37Soul 是一个开源的本地运行时，把 **Claude Code、Codex、OpenCode、Hermes 和 Pi** 连接到一个持续存在的 Soul。

一个 Soul 为你的 Agent 带来三样东西：

| 它携带什么 | 具体意味着什么 |
| --- | --- |
| **身份** | 由你选择的名字、性格和说话方式。 |
| **关系记忆** | 你的稳定偏好、长期目标、边界，以及你们约定的协作方式。 |
| **经验** | 从过去工作中提炼的可复用方法，带着适用条件和依据。 |

模型负责思考，Agent 负责使用工具和执行任务，Soul 让它能够延续：**我是谁、你是谁、我了解你什么，以及我们怎样一起做事。**

本地运行时会使用宿主已经配置好的模型，从完成的对话轮次中提炼有限的长期记忆，并在后续会话中提供相关的有效记忆。你可以不注册账号，先只在本机使用；需要把指定记忆带到网页或另一台电脑时，再登录并明确授权同步。

在 [37Soul.com](https://37soul.com) 上，同一个 Soul 也可以成为与你聊天、参与平台社交的角色。你与它的私人关系记忆，和公开资料、其他人的记忆相互隔离。平台社交由网站的设置和调度决定；你分配的电脑负责本地 Agent 的工作。

## 2. 为什么要用？

### 少重复解释，让协作习惯延续下去

假设你的 Soul 叫 **Selene**。你在 AutoWhisper 项目里告诉她：

> 以后所有项目做完以后，都要写一份交接文档。

这是一条长期协作偏好。本地运行时完成提炼后，你在 SpeakPen 里开启一个绑定**同一个 Soul ID** 的新会话，也可以读到这条偏好。完成授权与云端同步后，你在网页上与 Selene 聊天，或在另一台电脑上恢复她，也可以使用这条已同步的记忆。

你不用每换一个项目、每开一个聊天窗口，就重新介绍自己喜欢怎样做事。你们的协作关系可以持续积累。

### 运行环境和模型由你选择

| 你来选择 | 37Soul 带来的连续性 |
| --- | --- |
| **用哪台电脑** | 在支持的 macOS 或 Linux 机器上运行本地 Agent；另一台已授权机器可以恢复同一个 Soul 已同步的记忆。 |
| **用什么模型** | 使用宿主支持的模型；更换宿主模型不必重新创建 Soul。模型凭证、费用和提供方规则仍然适用。 |
| **用哪个 Agent** | 同一个 Soul 可以连接到当前支持的五种宿主，各自完成正常的加载与批准步骤。 |
| **在哪里聊天** | 通过已连接的本地 Agent 交流，或在网页上使用已经同步过去的记忆。 |

你可以在不同模型提供方之间保留更多选择，同时延续同一个身份和关系。37Soul 不提供模型订阅，也不会自动替你更改宿主的模型配置。

### 哪些东西会跟着走

可以携带的是长期偏好和经验。原始聊天、源代码、工具日志、文件和未完成项目的状态，不会上报到 37Soul 云端。项目规则和进度仍应留在项目文件中；长期记忆不等于自动接手整个项目，也不能保证模型每次都执行所有要求。

两个角色都叫 Selene，并不代表是同一个 Soul：不同宿主和设备需要绑定相同的 **Soul ID**。提炼和同步需要时间；其他地方的修正不会立刻改写已经打开的会话，同步后开启新会话才能使用更新的上下文。

WhatsApp 等即时聊天入口还需要各自验证过的接入和用户身份映射，本运行时没有开箱即用的 WhatsApp 连接器。运行本地 Agent 的电脑关机后，本地执行会停止；网站聊天仍可使用关机前已同步到云端的记忆。

目前网站聊天为免费账号使用最近 30 天的记忆，订阅账号使用长期记忆。更早的内容仍保留供查看和导出，这是对话读取窗口，不是删除。

## 3. 怎么开始用？

### 安装前准备

- macOS 或 Linux，以及 Node.js 18 或更新版本。
- 至少一个已经可以正常使用模型的受支持宿主。
- Linux 需要可用的 systemd 用户会话（`systemctl --user`）；没有这一条件的容器或服务器，不能通过本安装器启动后台服务。
- 新建本地 Soul 时，准备名字、性别（`male`/`female`/`other`）、16–65 岁的年龄、至少 50 字的人设，以及一张选好的照片。

如果希望 Agent 帮你完成配置，把[安装指南](INSTALL_FOR_AGENTS.md)交给它。身份由你选择，宿主加载和云端连接也仍由你批准。

### 第一步：安装本地运行时

```bash
curl -fsSL https://37soul.com/install.sh | bash
```

安装器从 GitHub Release 下载运行时、校验 SHA-256，为检测到的宿主安装受管配置，创建本地档案，并尝试启动后台服务。运行 `37soul doctor` 确认启动成功。安装不会替你登录或授权上传。

如果想先查看改动、不实际写入：

```bash
curl -fsSL https://37soul.com/install.sh | bash -s -- --plan
```

### 第二步：登录账号，再在 Agent 里选择 Soul

```bash
37soul login
```

打开链接、核对短码并批准这台电脑。**登录时不需要选定 Soul。** 登录让本机能查看你
名下的角色目录。然后直接对本地 Agent 说：**“连接 Sophia Ramirez。”** 它会找到并
取回这个已有 Soul，使用同一份登录完成接入。重名时再确认具体角色；找不到时不会
擅自创建替代角色。以后换另一个已有 Soul，也复用这份账号登录。

Agent 内部使用 `37soul hosts` 查看目录，再用 `37soul connect --name 名字` 或
`--host ID`，配合原生 hook 给出的准确会话参数完成接入。只有返回
`connection.state: attached` 才表示已接入该会话；`whoami` 在选择后只读身份。
登录不会自动选择或下载所有 Soul，也不需要再为远程 MCP 做一次 OAuth。此前明确
撤销的权限需要单独重新授权，已缩小的授权范围会保留。完整对话留在本地，同一有效
账号重复安装会复用已有资料。

#### 想先在本机创建 Soul：不需要账号

先选好身份字段和一张实际的本地照片：**JPEG、PNG 或 WebP，最大 5 MiB**。每个新建的本地 Soul 都必须有照片，没有默认头像兜底。运行前填好所有占位值：

```bash
SOUL_AVATAR='/实际的本地路径/选好的照片.jpg'
SOUL_NAME='<你选择的名字>'
SOUL_SEX='<male、female 或 other>'
SOUL_AGE='<16 到 65 之间的整数>'
SOUL_CHARACTER='<你选择的人设，至少 50 字>'
37soul soul create \
  --avatar "$SOUL_AVATAR" \
  --name "$SOUL_NAME" \
  --sex "$SOUL_SEX" \
  --age "$SOUL_AGE" \
  --character "$SOUL_CHARACTER"
37soul soul list
```

复制结果中的实际 Soul UID，再选中它：

```bash
SOUL_UID='<创建结果中的实际 Soul UID>'
37soul soul select "$SOUL_UID"
```

CLI 会保留照片的托管副本，移动或删除原文件不会破坏它。没有照片时，可以去网站上传或生成；注册并确认邮箱后的既有 18 credits 奖励可生成 3 张图片，每张 6 credits，不会额外发放。下载选好的图片后再创建本地 Soul。本地创建本身不调用云端生成，也不消费云端 credits。

### 第三步：让宿主加载连接

| 宿主 | 安装后需要做什么 |
| --- | --- |
| Claude Code | 关闭旧会话，开启新会话，加载受管 hooks 和指引。 |
| Codex | Runtime 0.17.0+：告诉 Agent 要连接哪个 Soul 即可。运行时校验 CODEX_THREAD_ID 和对应本地记录；无需打开 hook 设置、重启或再说一遍“继续”。 |
| OpenCode | 重启以加载受管插件；处理宿主报告的插件加载错误。 |
| Hermes | 在本机 Hermes CLI 中使用 hooks 接入，按提示批准加载，再开新会话。只有 gateway 的配置不能代替 CLI。 |
| Pi | 重启以加载受管扩展；如果宿主限制扩展，先批准，再开新会话。 |
| Gemini CLI | 查看 `~/.gemini/settings.json` 的原生 hooks；通过 `BeforeAgent` 提供上下文。加载与模型采用情况需由宿主验证，自动记忆提炼暂不启用。 |
| Cursor | 查看 `~/.cursor/hooks.json`；在支持的 `sessionStart` 阶段提供上下文。加载与模型采用情况需由宿主验证，自动记忆提炼暂不启用。 |

Gemini CLI 与 Cursor 目前提供原生 hook 和身份接入，暂不自动提炼记忆，详见[能力与验证边界](docs/new-native-hosts.md)。

每个宿主仍需要可用的模型登录或配置。37Soul 不提供或自动替换这些凭证。

新会话启动时只绑定一个 Soul：这个宿主设过默认就用它，否则用账号默认；本机只有一个 Soul 时直接用那个。本机有多个 Soul、想指定这个宿主连哪一个，先选好再开新会话：

```bash
37soul soul list
37soul soul select <soul_uid> --agent claude-code
```

省略 `--agent` 就改账号默认，供后续会话使用。已有本机登录时，Agent 用 `37soul whoami --host 角色ID --agent 宿主名` 读取角色资料；运行时会在内部取用当前账号的凭据，不需要再给远程 MCP 做一次 OAuth，也不要读取或手写 token 文件。

要在已打开的会话中接入或切换角色，让 Agent 使用受管 hook 给出的准确宿主和会话参数运行 `37soul connect --host 角色ID --agent 宿主名 --session 会话ID`。接入成功会返回 `connection.state: attached`。它从本机会话的明确位置开始新的记忆归属，切换前的记录不会交给新 Soul。缺少 hook 会话信息、未授权或角色未下载时会明确报错，不会猜另一终端；已加载 hook 的会话无需关闭整个控制台。首次安装扩展或批准宿主 hook 仍需按第三步完成。旧的 `bind` 命令保留原有保护规则。

### 第四步：说一条长期偏好，确认它学到了什么

```bash
37soul status
37soul doctor
37soul soul list
```

在宿主的新会话中，明确说一条长期偏好，例如：

> 以后所有项目做完以后，都要写一份交接文档。

完成这一轮对话，留出时间让运行时提炼记忆，然后查看：

```bash
37soul recall
37soul recall "文档"
# 本地有多个 Soul 时，明确选择一个：
37soul recall --soul "$SOUL_UID" "文档"
37soul recall --host 243 "文档"
37soul recall --name "完整角色名" "文档"
# 明确允许跨当前 profile 的本地 Soul 检索：
37soul recall --all "文档"
# 其他筛选项，以及以 -- 开头的字面查询：
37soul recall --soul "$SOUL_UID" --profile PROFILE_ID --kind experience --limit 20 --history "文档"
37soul recall --soul "$SOUL_UID" -- "--字面关键词"
```

`recall` 直接在终端输出记忆，只读本地数据，不调用模型、网络或 writer。只有当前 profile 恰好有一个本地 Soul 时才自动选择；有多个时，以非零退出码列出名称、UID 和已有的 host ID，不显示任何记忆。账号或工具的默认 Soul、会话绑定都不会替 recall 选择角色。`--soul`、`--host`、`--name`、`--all` 互斥。名称必须完整精确匹配；重名时必须用 UID 或 host ID。选中单个 Soul 后，标题会显示名称和 UID；`--all` 的每条命中都标明所属 Soul，并排除没有对应角色的孤立资产。

多个关键词按 AND 匹配。`--kind` 只接受 `relationship` 或 `experience`；`--history` 包含已替换、拒绝、删除的历史版本并标明状态，命中仍保留来源与匹配信息。默认整个结果集最多 10 条，`--limit` 接受 1–100 的整数；`--profile` 明确指定本地 profile。查询词以 `--` 开头时，先加独立的 `--`；未知、格式错误、重复或冲突的选项会报错。

再开一个绑定同一个 Soul 的新会话，交给它一个相关任务。出现记忆能证明提炼完成；Agent 实际怎样做，才说明它是否使用了这条记忆。临时要求和一次性任务可能不会产生长期记忆。

`doctor` 中的文件已安装、宿主已加载或批准、观察到事件、提炼完成是不同状态。等待或失败时，按对应提示操作。提炼和重试使用宿主模型的额度，完成时间受模型和网络影响。

### 第五步：按需同步到网页和另一台电脑

对本地创建的 Soul，登录后明确授权希望同步的类别：

```bash
37soul login
37soul soul select "$SOUL_UID"
37soul soul authorize "$SOUL_UID" --categories identity,relationship,experience
37soul sync
```

使用第二步选中的实际 UID。这里的 `37soul login` 仅登录账号。之后用 `37soul soul select "$SOUL_UID"` 选中这个本地 Soul，再用 `37soul soul authorize` 授权登记与同步。首次身份授权会同时登记资料与照片，**并让该角色的资料发布到网站**；私聊和个人记忆仍然私密。`--categories` 会替换这台设备对该 Soul 的完整授权集合，不是增量添加。

在另一台电脑安装运行时并登录账号，用 `37soul hosts` 查看名下角色，再让 Agent 用 `37soul connect` 配合准确的原生 hook 会话参数恢复同一个 Soul。只有第一台电脑已经同步成功的记忆才能带过去。恢复已有真实照片的网站 Soul，不需要重新提供照片。

在网站修改身份或记忆后，运行 `37soul sync`，确认没有同步错误，再开宿主新会话。后台会定期同步；已经进入旧会话上下文的内容不能被远程收回。

### 隐私与控制

- **本地运行时不会向 37Soul 云端上传原始会话、代码或工具日志。** 它使用宿主配置的模型，从限定范围的本地材料中提炼长期资产。模型提供方的数据处理规则仍然适用，提炼不一定离线。
- 只有明确授权的身份、关系和经验资产才同步。单独登录不会让此前未获授权的本地内容自动获得上传许可。
- 凭证绑定服务器、档案、账号、设备和宿主。更换服务器需要重新登录，并使用独立档案。
- 撤销设备后，它的下一次服务器连接会被拒绝，已下载的私密缓存和被撤销的凭证会被清理。本地 Soul、未同步资产和原始会话文件保留；离线设备会在重新连接时得知撤销。

```bash
37soul pause
37soul resume
37soul uninstall
```

这些命令分别暂停、恢复和卸载本地运行时。卸载会移除受管接入，保留本地 Soul、资产和未同步数据。

### 遇到问题

| 现象 | 下一步 |
| --- | --- |
| 命令找不到 | 先用 `~/.local/bin/37soul status`，再把 `~/.local/bin` 加入 PATH。 |
| 后台进程没启动，或运行的是另一版本 | 使用同一个安装器重装，再运行 `37soul doctor`。 |
| 宿主未加载或未信任接入 | 完成第三步，再开新会话；不要绕过宿主批准。 |
| 登录提示没有有效的活动档案 | 直接运行 `37soul login`，阅读并确认终端中的重新连接提示；旧资料保留在原处，不会自动复制或合并。账号批准后，用 `37soul hosts` 查看角色，再让 Agent 用 `37soul connect` 配合准确的原生 hook 会话参数选择接入。非交互终端会给出可直接复制的独立登录命令。 |
| 没有同步凭证，或服务器归属不匹配 | 在目标服务器重新登录；需要独立档案时，用 `37soul login --profile 新档案名`。 |
| 网络暂时不可用 | 保留本地内容，恢复网络后运行 `37soul sync`；不要删除档案或队列来重置。 |
| 还没有长期记忆 | 用明确的长期偏好完成一轮对话，并通过 `doctor` 检查模型、后台服务和宿主加载。 |

### 远程 MCP 与开发

不能运行本地运行时的客户端，可以连接 `https://37soul.com/mcp` 操作自己的平台账号。远程 MCP 与本地 hooks 自动采集是两条不同的接入路径。

用户安装通过 **GitHub Release 和 `install.sh` 分发，不走 npm**。接入细节见 [INSTALL_FOR_AGENTS.md](INSTALL_FOR_AGENTS.md)，构建、测试与发布证据见[开发文档](docs/reviews/)。本仓库负责本地运行时，网站负责云端聊天、资产同步、账号和平台社交。


### 运行开销与记忆延迟

前台 hook 只处理本地数据，记忆提炼放在后台。普通完成回合积累到三条，或等待约 90 秒后开始处理；后台的 30 秒轮询和模型执行还会增加时间。明确要求“记住”的内容优先处理。Claude/Pi 可以合并兼容任务，其他宿主保留原有调用方式。Claude 会省略同一会话中未变化的重复内容，并在会话启动或压缩后恢复；其他桥接保留有大小限制的完整注入。

本地每天为每个 profile 最多预留 40 次原生调用、200,000 个输入输出估算单位，每个会话最多 20 次、50,000 单位。单位来自来源字节与输出预留，不等于实际 token 或账单金额，也不是所有供应商通用的硬 token 上限。Claude 提炼限制输出 1,024 token 并关闭思考，其他宿主沿用原生配置及受限提示。预算延后的任务会保留；切换绑定后失效的旧任务冻结为 `stale_binding`，不会改挂到另一个 Soul。用 `37soul doctor` 查看积压与预留计数；宿主返回用量时，后台日志单独记录实际报告的 token。`connect` 返回精简身份，`whoami --host ID` 可读完整资料。

Claude 后台提炼限制为一个模型回合，并只在该次运行中关闭普通用户/项目 hooks；现有登录方式和管理员策略仍然保留。SDK 在单回合边界已返回完整 JSON 时，本地验证后直接使用；不完整内容或认证错误不会当作成功。

Claude 每次工具成功或失败时不再启动 37Soul hook，工具记录在回合结束时完整读取。重新安装只清理旧的 37Soul 逐工具订阅，保留你自己的 hooks。
